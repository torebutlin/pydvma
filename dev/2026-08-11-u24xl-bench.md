# ESI U24 XL bench characterisation (2026-08-11)

Setup: MacBook Pro 14" M4 Pro (Mac16,8), macOS jack output → U24 XL
L+R line inputs (Tore's wiring; no other cables available). All
measurements via a scratch harness driving the jack and capturing the
U24 XL with both clocks pinned through `pydvma._coreaudio`; the
durable subset is automated in `dev/u24xl_hw_check.py` (13 checks,
13/13 on first run).

This was the "pending bench characterisation" flagged in
`dev/2026-08-11-audio-daq-device-survey.md` for the fixed-gain
station-box candidate.

## What CoreAudio exposes (software-settable)

- **Native rates: 8000, 16000, 32000, 44100, 48000 Hz.** The manual
  admits only 32/44.1/48 k; 8 k and 16 k are real (see anti-alias
  below), a genuine DAQ bonus the 2i2 lacks (its ladder stops at
  44.1 k, so low-fs logging there always oversamples + decimates).
  48 kHz ceiling confirmed (USB 1.0 audio class, full speed).
- **Input volume, per channel, −40..+12 dB — DIGITAL.** ESI's manual
  calls it "I2S input gain (12dB)"; measured SNR is IDENTICAL at 0 and
  +12 dB (28.7 vs 28.9 dB on a fixed analogue tone) and attenuation
  loses SNR against a fixed post-scale floor, so it only rescales
  data. pydvma pins it to 0 dB per stream (restored after).
  NB the dB property REFUSES direct writes (silently — set succeeds,
  value unchanged); only the scalar property works, hence the
  bisection in `_coreaudio.set_input_volume_db`.
- **Capture bit depth: macOS parks the device at 16-bit** even though
  24-bit is available, and a nominal-rate change RESETS it to 16.
  pydvma raises it to 24 per stream. (The analogue floor dominates at
  48 k, but at 8 k the in-band floor sits within ~4 dB of the 16-bit
  dither floor, so 16-bit would genuinely cost dynamic range there.)
- **Input source selector: line vs S/PDIF**, software-settable
  (`'ssrc'` — not currently used by pydvma; the optical input could be
  a future cable-free digital loopback if a TOSLINK loop is fitted).
- Output volume −55..0 dB per channel (digital, at 0 by default);
  mute switches on both scopes.

## Levels (the absolute-voltage triangle)

Three independent numbers agree to better than 0.1 dB:

1. ESI's published max input: **+4.7 dBu = 1.331 Vrms = 1.882 Vpk**
   (user's guide §6, "Input Level (0dB): +4.7dBu").
2. Apple's jack runs impedance-detected output modes (<150 Ω:
   1.25 Vrms; 150 Ω–1 kΩ: 3 Vrms; line-level devices: its own mode).
   Into the U24 XL the measured captured peak at full drive was
   0.7456 FS, which back-computes the jack's **line-level mode as
   1.000 Vrms full-scale** if ESI's spec is exact — self-consistent to
   0.07 dB.
3. The end-to-end check in `u24xl_hw_check.py`: 0.1 digital peak at
   jack 0 dB → predicted 0.1414 Vpk → **measured 0.1414 Vpk
   (−0.00 dB)** through the full pydvma path with `VmaxSC`
   auto-derived (1.8819 V) and the input volume deliberately mis-set
   (the pin protected the scale).

The Mac could NOT clip the U24 XL (max drive reaches 75% FS), so the
clip point was not directly observed; absolute confirmation against an
independent source (Rigol DG1022Z + `verify_input_scaling`) stays on
TODO until a BNC→RCA/TS cable exists. The jack's dB volume readback
tracks real attenuation within ~0.2 dB over 0..−20 dB but goes wild
below −30 (16.5 dB step for a set 10) — calibration should pin 0 dB,
never interpolate the scale.

## Performance (via the jack, so lower bounds where the source limits)

| Metric | 48 kHz | 8 kHz native |
|---|---|---|
| Noise floor (in-band, gain 0) | −79 dBFS (20 Hz–20 kHz) | −94 dBFS (10 Hz–3.8 kHz) |
| Effective bits (from DR) | ~12.8 | ~15.3 |
| Alias rejection (deep) | 76 dB (30 kHz tone) | 69–72 dB (5 kHz tone) |
| Alias rejection (1 kHz past Nyquist) | 18 dB (25→23 kHz) | — |

- The 48 k floor carries excess HF noise (white scaling from the 8 k
  band predicts −87, measured −79): delta-sigma shaping in the top
  octave. For vibration work at low fs the 15+ bit figure is the
  relevant one.
- Noise includes the CONNECTED Mac jack amp — the U24 XL alone may be
  better; separating needs an unplugged-input capture (30 s with the
  cable out, some day).
- Frequency response: flat ±0.15 dB 20 Hz–22 kHz, −0.75 dB at 10 Hz
  (AC coupling), −1.35 dB at 23 kHz. Channel gain match 0.01 dB;
  inter-channel phase 0.07° at 1 kHz / 0.66° at 10 kHz (delta-sigma
  per-channel ADCs — effectively simultaneous).
- THD through the whole chain: 0.018 % at −2.5 dBFS, floor-limited
  (constant ≈ −81 dBFS harmonic residue at all drives — likely the
  Mac headphone amp's, not the ADC's).
- Combined clock offset vs the Mac: **−0.3 ppm** over a 10 s measure.

## vs the Scarlett 2i2 4th Gen

| | U24 XL (£63) | 2i2 4th Gen |
|---|---|---|
| Gain | NONE analogue; digital ±dB pinned by pydvma → nothing to mis-set, `VmaxSC` auto-derived | Analogue knob, unreadable by any API → operator must state it |
| Native rates | 8k–48k (low rates real, AA tracks fs) | 44.1k–192k (low fs only via oversample+decimate) |
| Full scale (line) | +4.7 dBu fixed | +22 dBu..down (gain-dependent) |
| Channels | 2 analogue (+ S/PDIF pair alt.) | 2 analogue + 2 loopback |
| Self-test | needs a cable (jack loop) — no digital loopback path in class mode | built-in digital loopback ch 3/4 |
| Headroom/quality tier | consumer codec, ~13 bit wideband / 15+ bit low-fs | proper 24-bit converter path, quieter |

Verdict for the survey lineup: exactly as hoped — the U24 XL is the
"nothing to mis-set" station box (now literally true: pydvma pins the
one thing that WAS settable), the 2i2 remains the better-converter
adjustable bench box.

## Quirks for the record

- The LEFT output jack doubles as a stereo headphone out (right must
  be unplugged for headphones) — manual §2.
- Windows enumeration name not yet captured; the profile matches
  'u24xl'/'u24 xl' + vendor 'esi' — verify on the PC and add the
  WDM-KS product-id token if needed (TODO).
- Mismatched per-channel input-volume values (e.g. `{1: +5.0,
  2: -6.0}`) ARE possible — seen mid-bench after scalar experiments —
  which is why the Recorder's restore is per-element rather than
  one-value-for-all.
